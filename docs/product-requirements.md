- 产品形态：Windows、macOS、Linux 桌面应用
- 核心原则：本地优先、隐私优先、用户拥有数据、外部传输可见且可控

## 1. 产品愿景

PaperMind 帮助研究者在一个本地桌面工作区中完成论文收集、阅读、批注、理解、问答和笔记沉淀。论文原文件、元数据、批注与生成结果默认保存在本机；只有用户明确触发 AI 操作时，完成该操作所需的最小上下文才可发送给配置的 AI Provider。

PaperMind 不在首版承担云盘、协同编辑、知识图谱或双向笔记同步职责。

## 2. 目标用户与核心任务

### 2.1 主要用户

- 需要长期阅读和整理 PDF 论文的学生、研究者和工程师。
- 希望借助 AI 理解论文，但要求明确知道哪些内容会离开本机的用户。
- 使用 Obsidian 和 Git 管理长期研究笔记的用户。

### 2.2 核心任务

1. 将本地 PDF 导入一个受 PaperMind 管理的论文库。
2. 按标题、作者、标签或全文快速找到论文。
3. 阅读 PDF，搜索文本，创建高亮和批注，并恢复上次进度。
4. 对选中文本执行翻译或解释。
5. 针对当前论文提问，并从回答引用跳转回原文位置。
6. 生成可编辑的摘要和结构化笔记。
7. 将笔记单向导出到用户选择的 Obsidian Vault。
8. 使用系统 Git 凭据把 PaperMind 导出的笔记提交并推送到已有远程仓库。

## 3. 产品原则

### 3.1 本地优先

- PDF、元数据、阅读进度、批注、笔记、对话记录和向量默认保存在本地。
- 不要求 PaperMind 账户或 PaperMind 云服务。
- 数据库不可用或 AI 未配置时，文献管理和阅读能力仍应可用。
- 用户可以定位、备份和迁移自己的论文库。

### 3.2 隐私优先

- AI 功能默认关闭，配置 Provider 后仍须由用户主动触发请求。
- UI 在首次发送前说明 Provider、将发送的数据类型和隐私影响。
- API Key 不以明文写入 SQLite、日志、源码、Git 或导出笔记。
- 不在后台自动上传论文，不做隐式遥测；未来如加入遥测，必须独立选择加入。

### 3.3 可追溯

- AI 回答中的事实性结论应尽可能带有论文页码和可跳转引用。
- 生成笔记标记生成时间、模型和来源论文，但不得暴露密钥。
- 文件导入、导出和 Git 操作给出明确结果，不把失败表现为成功。

## 4. 核心用户流程

### 4.1 首次启动

1. 应用说明本地数据原则，并自动使用系统文档目录下的 `PaperMind Library`；用户可随后在设置中迁移到其他目录。
2. 用户可跳过 AI 配置，直接使用本地阅读能力。
3. 用户需要 AI 时再选择 Provider、模型并安全保存 API Key。
4. Obsidian Vault 和 Git 仓库均为后续可选配置，不是首次启动门槛。

### 4.2 导入和整理

1. 用户通过系统文件选择器选择一个或多个 PDF。
2. 应用校验文件类型、大小和内容摘要，按 SHA-256 去重后复制到托管目录。
3. 应用提取可用的标题、作者和正文；用户可修正元数据。
4. 论文进入资料库，可添加标签、单层集合和自由笔记。
5. 加密、损坏或无文本层的 PDF 给出明确状态，不阻塞其他文件导入。

### 4.3 阅读和批注

1. 用户打开论文，应用恢复上次页码和缩放状态。
2. 用户可搜索全文并在页面中定位结果。
3. 用户选择文本后创建高亮、批注，或主动触发翻译/解释。
4. 高亮使用文本引用和位置选择器持久化；渲染矩形仅作定位辅助。

### 4.4 单论文问答

1. 用户在当前论文中提出问题。
2. 应用本地检索相关文本切片，并在发送前显示将使用的 Provider。
3. 主进程仅向 Provider 发送问题、必要切片和受控提示词。
4. 回答以流式方式呈现，引用可定位到页码和原文片段。
5. 无可靠来源时，回答明确说明证据不足。

### 4.5 笔记生成与导出

1. 用户主动生成摘要或结构化笔记，并可在本地编辑。
2. 用户通过系统目录选择器授权一个 Obsidian Vault。
3. 应用在 Vault 的专用子目录中创建新的 Markdown 文件。
4. MVP 不读取或合并用户已有笔记，不自动覆盖同名文件，也不把 Vault 内容反向导入 PaperMind。

### 4.6 Git 推送

1. 用户选择已初始化的本地 Git 仓库，通常是 Obsidian Vault。
2. 应用检查 Git 可执行文件、仓库状态、远程和上游分支。
3. 应用只暂存本次由 PaperMind 导出的文件，创建明确的提交并推送。
4. 认证交给系统 Git Credential Manager、系统凭据助手或 SSH agent；PaperMind 不接收或保存 GitHub Token。
5. 遇到暂存冲突、非快进拒绝或认证失败时停止；MVP 不自动合并或强制推送。

## 5. 功能范围

### 5.1 MVP

| 能力 | MVP 验收边界 | 对应模块 |
| --- | --- | --- |
| 文献收集 | 文件选择、复制入库、SHA-256 去重、基础元数据编辑 | Library、File Store、Ingestion |
| 文献管理 | 列表、详情、集合、标签、标题/作者/全文搜索 | Library、Search、SQLite |
| PDF 阅读 | 连续/单页阅读、缩放、页码、文本搜索、恢复进度 | Reader、PDF.js |
| 高亮批注 | 文本高亮、颜色、Markdown 批注、编辑和删除 | Annotation |
| 翻译解释 | 对明确选中文本发起请求，结果可保存为笔记 | AI Service |
| 单论文助手 | 当前论文 RAG、流式回答、页码和原文引用 | Ingestion、Retrieval、AI Service |
| 结构化笔记 | 主动生成摘要/方法/结论/局限，并允许编辑 | Notes、AI Service |
| Obsidian 导出 | Markdown 单向、创建新文件、冲突改名、无反向同步 | Export |
| GitHub 同步 | 调用系统 Git 对导出文件执行受限 add/commit/push | Git Service |
| 隐私设置 | Provider 配置、发送提示、密钥安全存储、删除 AI 数据 | Settings、Secret Store |
| 桌面发布 | Windows、macOS、Linux 可安装构建和基础发布说明 | Packaging、CI |

MVP 的 RAG 仅覆盖当前论文；不做跨库语义问答。无文本层 PDF 可阅读和手工批注，但 OCR 不作为 MVP 完成条件。

### 5.2 第二阶段

- DOI、Crossref 等公开元数据补全，并由用户确认覆盖字段。
- OCR 和扫描论文处理。
- 多论文工作区、跨论文语义搜索和向量索引扩展。
- 本地模型、兼容 API Provider 和本地嵌入模型。
- 引用格式、BibTeX/RIS 导入导出和参考文献识别。
- PaperMind 管理文件的增量重新导出，但仍不自动合并用户笔记。
- Git 拉取状态检查、冲突指导和可审阅的同步流程。
- 可选本地备份、数据库恢复和库完整性检查 UI。

### 5.3 远期候选

- Obsidian 双向同步和冲突合并。
- 知识图谱、概念关系和引文网络。
- 跨设备数据库同步、端到端加密云备份。
- 团队协作、共享批注和权限模型。
- 插件系统、移动端和浏览器采集器。
- 自动化研究工作流或有系统工具能力的 AI Agent。

以上能力在获得独立需求、威胁模型和数据迁移设计前不得提前进入 MVP。

## 6. 非功能要求

### 6.1 安全与隐私

- Electron Renderer 启用上下文隔离和沙箱，禁用 Node.js 集成。
- Renderer 不能直接访问 SQLite、文件系统、系统命令或任意网络端点。
- 所有特权操作通过类型化、白名单化且经运行时校验的 IPC 完成。
- 文件操作限制在论文库、用户本次选择的文件或获授权的 Vault/Git 根目录内。
- 详细要求见 `security.md`。

### 6.2 可靠性

- SQLite 使用迁移、事务、外键和 WAL；升级前创建可恢复备份。
- 文件导入、导出采用临时文件加原子重命名，避免半写入状态。
- 删除默认采用可恢复或延迟清理策略；永久删除需显式确认。
- AI、网络和 Git 失败不得损坏本地论文和笔记。

### 6.3 性能目标

- 典型资料库（5,000 篇且全文索引已建立）冷启动目标小于 3 秒，这是发布前测量目标而非 Phase 0 保证。
- 长任务不得阻塞主进程事件循环；解析、哈希和嵌入进入受控后台任务。
- PDF 页面按需渲染和虚拟化，不一次渲染全部页面。

### 6.4 可访问性与可移植性

- 主要阅读和批注操作支持键盘，焦点状态清晰，状态不只依赖颜色。
- 明确区分本地结果、AI 生成结果和外部同步状态。
- 路径使用平台 API，不假设路径分隔符；平台差异由 Main adapter 隔离。

## 7. 成功指标

- 用户可从导入 PDF 到创建首条批注，全程无需 AI 或账户。
- 有文本层的论文可完成全文检索、单论文问答和引用跳转。
- AI 请求前后的 Provider、发送范围、失败状态清楚可见。
- Obsidian 导出不改写已有用户文件。
- Git 推送不保存 Token、不暂存无关文件、不执行强制操作。
- 三个平台安装包通过启动、导入、阅读和数据持久化冒烟测试。

## 8. 明确不做

- MVP 不提供云账号、云端论文存储或云端数据库。
- MVP 不提供双向 Obsidian、自动合并或后台监视 Vault。
- MVP 不提供知识图谱、团队协作、跨设备同步或 OCR。
- MVP 不自动执行 `git pull`、merge、rebase、force push 或凭据管理。
- MVP 不允许 AI 直接调用文件、Shell、Git 或其他系统工具。

## 9. 已确认的产品决策

以下决策于 2026-08-08 确认：

1. PaperMind 继续使用现有 Python Git 仓库，与仓库内已有 Python/Jupyter 文件共存；后续阶段不得删除或覆盖这些既有文件。
2. 默认论文库自动使用“系统文档目录/PaperMind Library”，不强制首次启动选择。
3. MVP 只正式支持 OpenAI，实现仍通过 `AIProvider` 接口隔离。
4. Obsidian 每次导出都创建新文件；重复导出不覆盖 PaperMind 文件或用户文件。
5. Git MVP 只支持已有本地仓库、远程和上游；发现 hooks 时逐次提示，用户确认后执行。
6. AI 对话默认仅保存在本地，同时提供“不保存本次会话”和一键删除。
7. Phase 1 接受 pnpm、`better-sqlite3`、`electron-builder` 作为优先验证组合。
8. Linux 无安全存储后端时，API Key 只保存在当前会话内存，不写入磁盘。

标签/单层集合的最终组合和翻译默认目标语言可在对应功能阶段确认，不阻塞 Phase 1。
